MANUAL/01 — YOUR FIRST PULL REQUEST

HOW TO CONTRIBUTE TO OSCC

You don't need years of experience, a fancy degree, or a massive portfolio to contribute. Every senior engineer was once someone making their very first Git commit. This page walks you through everything step by step.

TERMINOLOGY/02 — GIT FUNDAMENTALS

WHAT DO THESE WORDS ACTUALLY MEAN?

If you're new to Git and GitHub, here is the plain English breakdown.

REPOSITORY (REPO)

THE PROJECT FOLDER

A repository is the master folder on GitHub containing all project files, history, documentation, and issues.

FORK

YOUR PERSONAL COPY

Forking clones a repository onto your own GitHub account so you can experiment freely without touching original code.

BRANCH

AN ISOLATED WORKSPACE

A dedicated workspace (e.g. fix/typo) where you write your changes without breaking the stable main branch.

ISSUE

A TASK OR BUG TICKET

A public discussion thread where bugs are reported, feature requests are discussed, and assignments are coordinated.

PULL REQUEST (PR)

YOUR PROPOSAL TO MERGE

A formal submission asking project maintainers to review your branch changes and merge them into the upstream repository.

CODE REVIEW

PEER FEEDBACK

A constructive peer conversation where maintainers review your PR, suggest polish if needed, and approve it for merging.

WORKFLOW/03 — STEP-BY-STEP CHEATSHEET

THE 9-STEP EXECUTION WORKFLOW

Follow these exact commands to make your contribution to any OSCC project.

STEP 01 & 02 // CHOOSE A PROJECT & FIND AN ISSUE

Visit github.com/Odisha-Students-Code-Community. Pick a repository like Odisha-Students-Code-Community.github.io or Connect.

Open the Issues tab and search for is:open label:"good first issue". Comment on the issue requesting assignment: "Hi! I'd like to work on this issue."

STEP 03 // FORK & CLONE TO YOUR LOCAL MACHINE

Click the Fork button on GitHub to create your personal copy. Then run:

BASH // CLONE
$ git clone https://github.com/YOUR_USERNAME/Odisha-Students-Code-Community.github.io.git
cd Odisha-Students-Code-Community.github.io
STEP 04 // CREATE A NEW BRANCH

Always create a dedicated feature branch. Name it clearly (e.g. fix/nav-typo or feat/add-project):

BASH // BRANCH
$ git checkout -b feat/my-new-contribution
STEP 05 & 06 // WRITE CODE & TEST LOCALLY

Open the code in your favorite editor (VS Code, Cursor, Neovim). Test locally using a quick static server:

BASH // LOCAL SERVER
$ python -m http.server 8000

Open http://localhost:8000 in your browser to verify your changes!

STEP 07 // COMMIT & PUSH TO YOUR FORK

Stage your files, write a clear descriptive commit message, and push:

BASH // COMMIT & PUSH
$ git add .
git commit -m "feat: improve responsiveness on projects grid"
git push origin feat/my-new-contribution
STEP 08 & 09 // OPEN PULL REQUEST, REVIEW & MERGE

1. Navigate to the original OSCC repository on GitHub.
2. A banner will appear: "Compare & pull request". Click it.
3. Fill out the pull request template describing what you changed.
4. Reference the issue: Closes #12.
5. A maintainer will review your code. Once approved, it will be merged into main! 🎉

CONTRIBUTE/04 — MULTI-DISCIPLINARY

NOT A CODER YET? YOU CAN STILL CONTRIBUTE.

Open-source needs documentation writers, designers, testers, and organizers as much as engineers.

DOCUMENTATION

TECHNICAL WRITING

Fix typos, write setup tutorials, improve code comments, or translate setup guides so other students can onboard faster.

UI/UX DESIGN

DESIGN & ACCESSIBILITY

Create brutalist layout mockups, design SVG icons, inspect WCAG color contrast, and report UI inconsistencies.

TESTING & BUG REPORTS

QA & ISSUE TRIAGE

Test our sites on your mobile phone, find broken links, and submit clear bug reports with screenshots and reproduction steps.

STANDARDS/05 — PR CHECKLIST

BEFORE YOU CLICK "SUBMIT PULL REQUEST"

  • [✓] My branch was created from the latest main branch.
  • [✓] I tested my changes locally and there are no console errors or broken links.
  • [✓] I did NOT commit personal secrets, API keys, or prompt scratch files.
  • [✓] My commit messages are clear, concise, and descriptive.
  • [✓] I am being respectful, constructive, and open to feedback during review.
